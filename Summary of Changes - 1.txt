STEP 1 — Fix the Acute Data-Destruction Bug
────────────────────────────────────────────────────────────────────────────────

What was changed in server.js:

1. New tables added to migrations (server.js lines ~485–508)
   - SquareConnection — multi-tenant token store (replaces single-tenant SquareAuth)
   - OAuthState — DB-backed OAuth state store (replaces in-memory Set)
   Both created via CREATE TABLE IF NOT EXISTS, matching the existing migrations pattern.

2. Killed the data-destruction bug (server.js line ~1048)
   BEFORE: DELETE FROM SquareAuth  ← wiped every user's tokens on every connect
   AFTER:  INSERT INTO "SquareConnection" ... ON CONFLICT ("userId") DO UPDATE SET ...
   The destructive DELETE is replaced with a per-user upsert. Each user's row is
   updated independently; no other user's tokens are touched.

3. Fixed SQLite placeholders (server.js line ~1054)
   BEFORE: VALUES (?, ?, ?, ?)
   AFTER:  VALUES ($1, $2, $3, $4, $5)
   PostgreSQL requires $N-style placeholders. SQLite-style ? caused a silent failure
   on every token save.

Temporary stand-in: merchantId was used as the userId key in SquareConnection until
Step 2 wired real SuperTokens userId through the OAuthState lookup.

STEP 2 — Thread userId Through OAuth
────────────────────────────────────────────────────────────────────────────────

Changes in server.js:

  What                                  Change
  ─────────────────────────────────────────────────────────────────────────────
  /api/square/oauth/callback location   Moved ABOVE app.use("/api", verifySession())
                                        Square's redirect carries no session cookie —
                                        it was getting a 401 on every connect. Auth is
                                        now handled via the state→userId DB lookup.

                                        CSRF check now always runs in all environments.

                                        Real userId is now stored in SquareConnection.

                                        connect.squareup.com. Respects SQUARE_ENV.

                                        /?square=error — frontend can show a toast
                                        (used in Step 6).

  /api/square/oauth/start               Added verifySession() middleware + async.
                                        Gets userId from req.session.getUserId().

  OAuthState                            Purges rows older than 15 minutes, then
                                        INSERTs state→userId mapping. DB-backed —
                                        survives server restarts and multi-instance
                                        deployments.

  activeOAuthStates in-memory Set       Deleted entirely — no longer needed.

  OAuth scopes (Bug 6 fix)              Added ORDERS_READ, PAYMENTS_READ,
                                        MERCHANT_PROFILE_READ to the scopes array.

STEP 4 — Encryption + Security Cleanup
────────────────────────────────────────────────────────────────────────────────

Changes in server.js:

  What                                  Change
  ─────────────────────────────────────────────────────────────────────────────
  encrypt(plaintext)                    AES-256-GCM with a random 12-byte IV per call.
                                        Output format: iv_hex:authTag_hex:data_hex.

  decrypt(ciphertext)                   Reverses encrypt(). Throws on bad key or
                                        tampered/corrupted ciphertext (GCM auth tag).

  _encKey() helper                      Reads TOKEN_ENCRYPTION_KEY from environment.
                                        Validates it is exactly 64 hex chars (32 bytes).
                                        Throws a clear message if missing or wrong length.

  OAuth callback (token storage)        accessToken and refreshToken now stored as
                                        encrypt(...) ciphertext. Plaintext tokens never
                                        touch the database.

  getSquareToken(userId)                Now returns decrypt(row.accessTokenEnc).
                                        The TODO Step 4 comment was removed.

  Bug 7 — token logging                 All console.log("🔐 Labor token source: ...")
                                        calls were already removed by Step 3's rewrite
                                        of getSquareLaborToken. Confirmed no traces
                                        remain after Step 4.

Doppler action required: add TOKEN_ENCRYPTION_KEY as a 64-char hex string.
Generate with: openssl rand -hex 32

STEP 5 — Token Refresh
────────────────────────────────────────────────────────────────────────────────

Changes in server.js:

refreshSquareToken(userId, row) — replaces the old refreshSquareLaborToken:

  Old                                   New
  ─────────────────────────────────────────────────────────────────────────────
  Read row.refreshToken (plaintext)     Decrypts row.refreshTokenEnc with decrypt()
  Updated SquareAuth by id              Updates SquareConnection by userId
  Stored plaintext tokens               Stores encrypt(access_token) and
                                        encrypt(refresh_token)
  Hardcoded connect.squareup.com        Uses getSquareBaseUrl()
  Threw raw error on failure            Sets status = 'error' in DB first, then
                                        throws — UI can detect and prompt reconnect
  Returned the full DB row              Returns just the plain-text access token,
                                        ready to use immediately

getSquareToken(userId) — now auto-refreshes:

  - Selects refreshTokenEnc and expiresAt in the same query (no extra round-trip)
  - Distinguishes 'error' status with its own clear error message
  - If expiresAt is within 7 days AND a refreshTokenEnc exists, calls
    refreshSquareToken(userId, row) transparently and returns the new token
  - Normal case (token not near expiry): returns decrypt(row.accessTokenEnc) directly
